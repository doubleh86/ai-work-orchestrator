# 수정 범위에 맞춘 검증

이 저장소 개발 작업의 기준은 [AGENTS.md](../AGENTS.md)의 검증 규칙이다.
**기본은 기존 정적 검사와 diff 확인이다. 테스트는 필요한 수정 부분만 선택하고 통과하면 끝낸다.**
이 기준은 앱이 대상 프로젝트에서 수행하는 검증 명령·통합 검증·승인 절차를 바꾸지 않는다.

## 범위 선택

| 수정 내용 | 기본 확인 |
|---|---|
| 문서·주석 | 내용·참조·diff. 명령 예제는 실제 정의와 대조 |
| 문구·스타일·동작을 바꾸지 않는 코드 수정 | 기존 정적 검사와 diff |
| 동작 변경·버그 수정 | 정적 검사 + 변경된 동작의 관련 테스트 파일·케이스 |
| 공용 계약·상태·저장 변경 | 위 검사 + 실제 영향을 받는 소비자·저장/복원 경계의 관련 테스트 |
| 빌드 설정·의존성·패키지 진입점 변경 | 변경한 산출물 확인에 필요한 빌드·패키징 검사 |
| CI·릴리스 또는 사용자 지정 검증 | 해당 작업에 명시된 검사 |

여러 파일을 고쳤거나 공통 파일을 건드렸다는 이유만으로 전체 테스트를 실행하지 않는다.
영향이 불명확하면 호출부를 읽어 관련 범위를 정한다. 광범위한 영향 때문에 전체 검사가
필요하면 어떤 영향인지 짧게 기록한다. 프로덕션 빌드·GUI 실행도 매번 덧붙이지 않는다.

## 필요한 명령만 선택

현재 `package.json`에는 별도 lint 스크립트가 없다. 타입·구문 검사를 정적 확인으로 사용하며,
검증을 위해 새 lint 도구나 의존성을 임의로 설치하지 않는다. 아래는 상황별 선택 예시이며
모두 차례대로 실행하는 목록이 아니다. 기존 개발·테스트 환경에서 실행한다.

| 목적 | 명령 예시 |
|---|---|
| TypeScript 정적 확인 | `npm run typecheck` |
| 수정한 Python 파일 구문 확인 | `python -m py_compile src/ai_orchestrator/mcp_server.py` |
| 관련 renderer 테스트만 | `node --test tests/renderer/maker-progress.test.cjs` |
| 관련 Python 케이스만 | `python -m pytest -q tests/test_maker_workflow.py -k background` |
| 변경한 diff의 공백 확인 | `git diff --check -- <수정 파일>` |

파일·케이스는 실제 수정 내용에 맞게 바꾼다. 테스트 파일이 크면 Python의 `-k` 또는 Node의
`--test-name-pattern`으로 필요한 케이스만 고른다. 정적 검사는 동작 테스트와 구분해 보고한다.

## 반복과 추가 기준

- 기존 관련 테스트가 해당 동작을 확인하면 새 테스트를 만들지 않는다. 놓치는 회귀 경계가 있을 때만 추가한다.
- 문구·CSS·내부 구현을 그대로 고정하는 검사나 단순 테스트 수 늘리기를 목적으로 한 검사는 추가하지 않는다.
- 정적 검사와 필요한 관련 검사가 통과하면 종료한다. 실패·새 변경·구체적 미해결 우려가 생긴 부분만 재확인한다.
- 작은 후속 수정이나 문서·보고서 정리 뒤에 통과한 전체 검사·빌드를 다시 돌리지 않는다.
- 과거 계획서의 전체 검사 명령·통과 개수는 당시 기록이다. 현재 수정의 검증 범위는 이 기준으로 다시 정한다.
- 완료 보고에는 실행한 확인과 결과, 필요한 검증을 하지 못했다면 그 범위와 이유만 간결하게 남긴다.
