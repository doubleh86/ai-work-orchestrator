# MCP 제어 후 UI로 진행 확인 넘기기

## 목표와 범위

외부 관제 AI는 사용자가 요청한 기획·제어를 수행하고 접수 결과를 알린 뒤 답변을 끝낸다.
지속적인 진행 확인·완료·실패·사용자 확인은 오케스트레이터 UI와 기존 알림이 담당한다.
사용자가 상태를 묻거나 후속 행동에 필요한 경우에만 MCP 상태를 조회한다.

현재 실행 요청은 이미 백그라운드 작업자에 전달되지만 MCP 도구 설명이 완료까지 반복 조회하도록
안내한다. 해당 설명과 새 채팅 연결 프롬프트를 함께 고친다. 접수와 실제 실행·완료는 구분하며
관제 답변을 끝내기 위해 MCP 프로세스를 종료하거나 연결을 끊도록 안내하지 않는다.
도구 인자·반환 형식·승인·실행 작업자·저장 상태·Git 부작용은 변경하지 않는다.

## 검증

실제 MCP 도구 목록에 전달되는 설명과 복사되는 연결 프롬프트의 전달 방침을 확인한다.
기존 백그라운드 접수·실패·중복 요청 검사, MCP 운영 검사와 renderer 관련 검사를 실행한다.
타입 검사·프로덕션 빌드·Python 컴파일과 diff를 확인한다.
실제 외부 AI의 응답 행동, 기존 연결의 설명 갱신, 배포 ZIP 반영은 로컬 검사와 구분한다.

## 결과

- MCP 도움말·실행 제어·상태 조회 도구 설명과 새 채팅 연결 프롬프트를 수정했다.
  접수 후 답변 종료, UI로 진행 확인 전달, 사용자 요청 또는 후속 행동에 필요한 조회만 안내한다.
- 접수를 실행·완료로 단정하지 않으며 답변 종료를 위해 MCP 프로세스를 종료하지 않도록 명시했다.
  실행·승인·반환 형식과 기존 백그라운드 실패·중복 요청 처리는 유지했다.
- `tests/test_maker_workflow.py`, `tests/test_mcp_operations.py`, `tests/test_mcp_source_watch.py` 27개 통과.
  실제 MCP 도구 목록으로 새 안내를 확인하고 백그라운드 즉시 접수·실패·재시도를 검증했다.
- renderer `maker-workflow.test.cjs` 26개, 타입 검사·Electron/renderer 빌드·Python compileall과 diff 검사 통과.
- 실제 Codex·Claude의 응답 행동과 기존 연결의 설명 갱신은 검사하지 않았다. 실행 중인 연결이나
  사용자 프로젝트를 조작하지 않았으며 공개 저장소 push·배포 ZIP 재빌드는 수행하지 않았다.
